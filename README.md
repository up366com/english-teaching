## 这是什么

天学网（北京天学网教育科技股份有限公司，up366.com）做的是英语教学的数字化，扎根北京中关村，
在合肥、海口、深圳、昆明、杭州、成都等地设有分公司。

这个仓库把「天学网到底提供什么」做成了可以跑、可以改、可以部署的代码，由三块组成：

- **一套完整的前台**：首页、产品体系、应用案例、新闻动态、品牌故事、资质与荣誉、团队、招聘、联系。
- **一套完整的后台**：11 类内容的增删改查、站点设置、媒体库、留言管理、管理员与审计。
- **一套完整的 GEO 能力**：每页单块 `@graph` JSON-LD、`llms.txt`、`sitemap.xml`、`hreflang`，
  让搜索引擎和生成式引擎（豆包、DeepSeek、千问、Kimi 等）能准确抓取、准确引用。

代码是干净的：无构建步骤、无前端框架、无 ORM 魔法。下载、安装、启动，三分钟看到完整站点。
下面这一章是站点的内容主体，也是理解所有文案与数据结构的前提。

## 产品体系

一句话概括：**天学网把 AI 放进英语教与学的每一个具体动作里**——不是做一个「AI 教育平台」的概念，
而是让课堂上的口语、作业里的作文、单元后的听写、联考前的模考，各有各的工具与数据出口。

### 三根支柱

产品不是零散工具的堆叠。整套体系由三根咬合的支柱驱动，缺一根就落不了地：

| 支柱 | 承担什么 | 落地形态 |
| --- | --- | --- |
| **天学大模型** | 能力底座：语音分析、自然语言处理、作文评估、学情建模 | 口语评测引擎、作文批改引擎、智能阅卷、个性化推荐 |
| **AI 智能体** | 把模型能力嵌进教师的工作流，而不是让教师去学一个新软件 | 备课、组题、批改、讲评、错题重组的流程化助手 |
| **强教研** | 决定「评什么、怎么评」的内核；模型不懂课标，教研懂 | 贴合新课标的题型设计、评分维度、分层标准与教学法 |

三者合起来的目标被内部概括为「双效」：**教师侧提效**（备课、批改减负），**学生侧见效**（针对性训练）。
站在教师侧，智能体扩展的是教师的知识边界与处理能力；站在学生侧，AI 推动的是从被动接收转向主动探索。

### 四条产品线

| 产品线 | 核心动作 | 一句话价值 |
| --- | --- | --- |
| [英语听说训练与口语评测](#一英语听说训练与口语评测) | 评、诊、练 | 把口语从「没法批量教」变成可评分、可追踪、可讲评 |
| [英语写作智能批改](#二英语写作智能批改) | 批、析、改 | 一个班的作文 5–10 分钟批完，且批得有依据 |
| [英语教学平台](#三英语教学平台) | 备、授、练、看 | 备课到学情在一个平台闭环，不用在多个工具间搬数据 |
| [听力·词汇·单词批改](#四听力词汇单词批改) | 听、写、记 | 把听力理解、听写、词汇记忆串成一条训练链 |

#### 一、英语听说训练与口语评测

站内页面：`/services/speaking-assessment`

**解决什么**：口语是英语教学里最难批量化的一环。一个班四十多人，逐个听、逐个纠，一节课时间根本不够；
学生练了很多，但错在哪个音、哪一处连读，谁也说不清。

**怎么实现**：口语评测引擎由天学大模型驱动，融合自然语言处理与多维度语音分析，
紧扣新课标题型（朗读、情景问答、话题表达），把评分颗粒度下沉到**单词重音、连读、语调起伏**这一级，
并形成「评测 — 诊断 — 推荐」的闭环。

**你会看到什么**：

- 逐句的标准发音示范与跟读对比，学生自己就能听出差异；
- 可视化能力雷达图与个性化学情报告，教师不用靠印象判断班级水平；
- 评测结果直接推送专项训练，薄弱点当堂补齐，而不是等到下次考试；
- 课堂、课后、机房模考**共用一套评测标准**，平时练的和最终考的口径一致。

口语评测引擎的调用量已突破 **48.8 亿次**（企业公开数据），说明这套评分口径已经在很大样本上跑过。

#### 二、英语写作智能批改

站内页面：`/services/writing-assessment`

**解决什么**：作文批改是英语教师最重的时间黑洞。传统方式一个班要数小时，且很难做到每篇都给到可执行的修改建议。

**怎么实现**：基于自研大模型，除识别语法、词汇、拼写错误外，还评估**逻辑与篇章结构**——
不止于把错挑出来，还要判断这篇文章「说得清不清楚」。

**你会看到什么**：

- 语法、词汇、搭配、拼写逐处标注，指到具体位置，学生知道改哪；
- 篇章结构评估，避免学生只会「改错字」而不会「重写一段」；
- **一个班 5–10 分钟完成批改**，教师的时间从誊抄分数转到设计讲评；
- 班级共性问题聚合视图：同一个搭配错误出现二十次，讲评课上就值得讲一次；
- 每位学生一份可执行的修改建议，批改结果直接进入讲评与作业闭环。

2026 年，这套英语作文 AI 批改项目获中国互联网创新大赛**数字教育专题赛一等奖**。

#### 三、英语教学平台

站内页面：`/services/teaching-platform`

**解决什么**：教师的日常在多个系统之间来回切：题库找题、网盘找课件、表格记成绩。
数据不在一处，学情就只能靠感觉。

**怎么实现**：一站式教学资源与工具，把备课、授课、作业布置放在同一个工作面上，
内置与教材同步的词汇清单、语法微课、阅读材料与配套练习。

**你会看到什么**：

- 资源按教材单元组织，**按难度分层**，同一个班可以布置不同版本的作业；
- 作业布置、提交、批改一体化，不用导出再导入；
- 班级与个人学情看板随课堂实时更新，讲评课有明确靶心；
- 校本资源可沉淀，教研组的成果能被下一届复用，不做一次性投入。

2024 年教师端完成 6.0 升级，备课与讲评链路进一步合并。

#### 四、听力·词汇·单词批改

站内页面：`/services/listening-vocabulary`

**解决什么**：听力、听写、词汇常被当成三件独立的事分别练，学生重复劳动，教师重复批改，
错词本永远是手抄的，抄完就忘。

**怎么实现**：把三件事串成一条可执行的训练链：

| 环节 | 做什么 | 关键细节 |
| --- | --- | --- |
| **试题泛听** | 与图书内容同步的分级听力 | 语速可按班级调整，应对高考听力语速变化，实现分层教学 |
| **全屏精讲** | 讲评课专用视图 | 精准定位高频错题，一键搜索同类题，小段音频播放，备课更省力 |
| **听写精练** | 听力文本在线编辑 | 自由挖空生成听写题，编辑后的试题可导出打印 |
| **练习报告** | 手机在线作答 | 系统即时自动批改，输出完整练习报告 |
| **错题重组** | 用真实错误出卷 | 创建错题试卷布置练习，也可导出打印 |
| **单词批改** | 听写纸扫描或拍照 | **2–3 分钟批完一个班**，自动生成年级/班级高频错词报告 |
| **班级错词本** | 二次复现 | 结合具体语境题型组卷，让错词在语境里再出现一次 |

词汇产品与教材单词同步，配释义例句，并用**词根词缀延伸**拓展词汇量，同时做发音规律训练——
记单词不只靠重复，还靠结构与读音。

### 八项能力，对应八个教学动作

产品线是「按场景分」，能力是「按动作分」。同一套引擎在不同动作上呈现为不同形态：

| 动作 | 能力 | 具体做什么 |
| --- | --- | --- |
| 测评 | 口语评测 | 朗读、情景问答、话题表达逐项评分，颗粒度到重音、连读、语调，附标准发音示范 |
| 批改 | 作文批改 | 拼写、语法、搭配、篇章结构自动处理，一个班 5–10 分钟 |
| 阅卷 | 智能阅卷 | 区域联考与校考答题卡扫描识别、自动评分，输出班级、年级、区域对比 |
| 听力 | 听力训练 | 按教材单元组织的分级听力集，逐题正确率与干扰项分析一并给出 |
| 词汇 | 词汇与听写 | 按单元组织词表，听写自动批改，错词本按真实错误重组练习 |
| 备课 | 备课资源 | 对齐新课标的课堂流程、课件与学案，可按班级二次编辑 |
| 学情 | 学情分析 | 把班级共性问题与学生个体差异分开呈现，讲评课有靶心 |
| 训练 | 个性化训练 | 依据错题类型、阅读偏好、写作短板重建练习，而不是全班一张卷 |

这八项没有「即将上线」。每一项都在学校日常使用，可以在一次真实课堂里演示。

### 产品落在哪些场景

| 场景 | 谁在用 | 主要用哪条线 | 产出 |
| --- | --- | --- | --- |
| **日常课堂** | 任课教师 + 全班 | 教学平台、听说评测 | 当堂练习数据、随堂讲评依据 |
| **课后训练** | 学生自主 + 教师布置 | 听力词汇、个性化训练 | 练习报告、错词本、推送的专项训练 |
| **区域联考** | 教研部门 + 多校 | 智能阅卷、学情分析 | 区域对比报告、共性问题清单 |
| **机房模考** | 学校 + 年级组 | 听说评测（与课堂同一套标准） | 模拟成绩、能力雷达图、备考建议 |

场景覆盖之所以重要：**平时练的口径和最终考的口径必须是同一个**，否则训练数据再漂亮也不迁移。

### 一次完整的教学闭环

天学网的产品逻辑不是「给教师一个工具」，而是把一节课前后的动作连成环：

1. **课前 · 备课** —— 按单元取资源、按班级调难度，课件与学案直接可用。
2. **课中 · 授课与随堂练** —— 听说练习当堂做、当堂评，雷达图即时可见。
3. **课后 · 作业与训练** —— 分层布置，系统按错题画像推送专项练习，减少无效重复。
4. **测评 · 批改与阅卷** —— 作文 5–10 分钟一班，答题卡扫描阅卷，数据自动汇总。
5. **讲评 · 学情与迭代** —— 共性问题进入讲评课，个体短板进入下一轮训练。

**闭环的价值在第五步**：如果批改结果不能变成讲评内容，批改就只是评分。
这也是「模型 + 智能体 + 教研」三根支柱必须同时存在的原因。

## 快速开始

### 环境要求

- **Node.js ≥ 22.5**（需要内置的 `node:sqlite`；用 MySQL 时可放宽到 18+）
- 无需构建工具、无需 npm 之外的全局依赖

### 三步启动

```bash
# 1. 安装依赖
npm install

# 2. 建库 + 灌入中英双语初始内容 + 创建管理员 + 生成 GEO 文件
npm run site:install -- --domain=https://www.up366.com --admin=admin --pass=你的密码

# 3. 启动
npm start          # 默认 http://localhost:3000
```

打开 `http://localhost:3000` 看中文站，`http://localhost:3000/en` 看英文站，
`http://localhost:3000/admin` 进后台。

## 后台怎么用

登录 `/admin` 后，左侧是能力清单，从上到下就是日常维护的顺序：

1. **控制台** —— 内容总量、最近发布、最新留言、GEO 状态。
2. **内容管理** —— 新闻资讯、应用案例、产品体系、自定义页面、招聘职位、团队与角色、一线反馈、
   首页幻灯片、合作与背书、发展历程、导航菜单。11 类内容共用一套列表 / 编辑界面，
   字段由 `config/content_types.json` 决定，加字段不用改代码。
3. **运营** —— 客户留言（含状态与来源页）、媒体库（上传、复用、删除）、GEO / SEO（结构化数据与
   `llms.txt` 预览、重新生成）。
4. **系统** —— 站点设置（分基础、联系、SEO、首页、社交、系统六组）、管理员账号与登录审计。

几个约定：

- 每个内容都有 **中文 / 英文两列**，只填中文时英文站自动回退显示中文，不会出现空白页。
- 排序字段 `sort` 越小越前；`status` 关闭即从列表与站点地图中消失。
- 图片走媒体库上传，编辑器里直接选，不用手写路径。
- 保存即生效，无需重启；`sitemap.xml`、`llms.txt` 由运行时按最新数据动态输出。

维护产品页时的三条规矩（对应上面产品体系的写法）：

- **能力写清楚，边界也写清楚**：每条产品页必须说明适用范围与不适用场景，不做无差别承诺。
- **数字必须有来源**：1.5 万所校、48.8 亿次这类数字要么来自公开报道，要么不进页面。
- **案例留余地**：案例页与产品页统一挂「不构成具体学校效果承诺」的免责说明。

详见 [docs/usage.md](docs/usage.md)。

## 双语是怎么实现的

三条规则，和多数「按浏览器语言自动跳转」的做法相反：

1. **语言只由 URL 前缀决定**：中文在根目录，英文在 `/en` 下。不读 Cookie、不读
   `Accept-Language`、不认 `?lang=`。
2. **切换语言的链接直接指向目标语言的同一页**，与 `<link rel="alternate" hreflang>` 完全一致，
   不做 302 中转。
3. **内容字段双列存储**：`title_cn` / `title_en`。取值时优先当前语言，缺了回退另一种语言。

为什么这么做：Googlebot、GPTBot 等抓取器默认发 `Accept-Language: en-US`。一旦按访客切语言，
中文首页会被当成英文抓取，`canonical` 与 `hreflang` 全部失准。URL 决定语言，爬虫和人都看到同一份东西。

产品与案例的英文不是机翻的占位文本：四条产品线的能力清单、六个案例的亮点、十五篇新闻的标题与摘要，
中英各自成文，语义一一对应。测试里有专门的成对检查，单边缺失会直接失败。

## GEO / SEO：让大模型读懂你的站点

这个项目把「生成式引擎优化」当成一等公民，而不是上线前补的 meta：

- **每页一块 `@graph` JSON-LD**，第一个节点必须是页面类型（`WebPage` / `AboutPage` / `CollectionPage` /
  `ContactPage`），且 `name` 与页面 `<title>` 逐字一致；其后按页面类型挂
  `Organization` / `Service` / `Article` / `FAQPage` / `BreadcrumbList` / `JobPosting` / `ItemList`，
  用 `@id` 互相引用，不重复描述同一实体。
- **`llms.txt` / `llms-full.txt`**：前者是站点结构与关键页面的导航式摘要，后者是可供模型直接读取的
  全量内容索引，中英各一份，运行时动态生成。
- **`sitemap.xml` / `robots.txt`**：自动包含全部有效页面，排除草稿与法律要求的 noindex 页面。
- **`hreflang` 与 `canonical`**：两种语言互为 alternate，避免重复内容互抢排名。

对产品型站点来说，这套东西的实际作用很具体：当有人问「英语作文批改哪个工具能一个班几分钟批完」，
模型手上得有能被引用的、带出处的句子，而不是一段形容词。

结构化数据样例见 [examples/](examples/)，字段约定见 [docs/api.md](docs/api.md)。

## 技术选型

| 决策 | 选择 | 原因 |
| --- | --- | --- |
| 运行时 | Node.js + Express 4 | 生态成熟，部署路径最短 |
| 模板 | 自研零构建 EJS（`#` 注释、`include`、布局继承） | 改一行 HTML 就能看效果，不引入打包器 |
| 数据库 | SQLite（默认）/ MySQL | 单机零运维起步，规模化可平滑迁移，SQL 完全一致 |
| 语言 | 原生 JS + CSS 变量 | 无框架、无 polyfill，首屏不需要 hydration |
| 安全 | CSP / CSRF / bcrypt / 蜜罐 / 限流 / SVG 净化 | 教育场景涉及未成年人，默认从严 |

## 数据库

默认 SQLite，文件在 `data/app.sqlite`，无需额外服务：

```bash
npm run site:install      # 建表 + 灌种子
```

切到 MySQL 只需环境变量，代码不用改：

```bash
HZ_DB_DRIVER=mysql \
HZ_DB_HOST=127.0.0.1 HZ_DB_PORT=3306 \
HZ_DB_NAME=up366 HZ_DB_USER=root HZ_DB_PASS=****** \
npm run site:install

npm run migrate:mysql     # 已有 SQLite 数据迁移到 MySQL
```

## 部署

装完依赖、跑一次安装脚本、起进程，三步就是全部：

```bash
npm ci --omit=dev
npm run site:install -- --domain=https://你的域名 --admin=admin --pass=你的密码
HZ_PORT=3000 NODE_ENV=production node server.js
```

也可以用 Docker：`docker compose up -d --build`，默认 8080 端口，首次启动自动安装。

支持部署在子目录（自动识别 `X-Forwarded-Prefix`）与纯静态导出（`npm run static:export`）。
反向代理配置、PM2、子目录细节、环境变量清单，见 [docs/quickstart.md](docs/quickstart.md)。

## 测试

五套测试，职责不重叠。前两套不需要起服务，后三套自己起独立实例、跑完自动关，可以反复跑。

| 命令 | 验的是什么 | 要不要先起服务 |
| --- | --- | --- |
| `npm run test:content` | 内容规则：新闻必有出处、案例必有免责、双语字段成对、无占位符与旧品牌残留 | 不要 |
| `npm test` | 全站回归：从 sitemap 抓全部页面，逐页校验 canonical / hreflang / JSON-LD / OG | 要（默认 `127.0.0.1:8099`） |
| `npm run test:security` | 安全基线：响应头、CSRF、限流、上传沙箱、路径穿越、Cookie 属性 | 不要 |
| `npm run test:admin` | 后台登录与各列表页可用性 | 不要 |
| `npm run test:crud` | 11 类内容的增删改查闭环 | 不要 |
| `npm run test:deploy` | 三种部署模式（根目录 / 子目录 / `X-Forwarded-Prefix`）的站内地址是否自洽 | 不要 |
| `npm run test:migrate` | SQLite → MySQL 迁移脚本自检 | 不要 |

`npm test` 默认连本机 8099 端口，换地址直接传：`node scripts/smoke.js https://www.up366.com`。

CI 跑的就是这一套，配置在 [.github/workflows/ci.yml](.github/workflows/ci.yml)：
内容检查 → 装库起服务跑全量回归 → 构建镜像并验健康检查。三关全绿才算能合。
